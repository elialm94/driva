## How to use this map (example)

Bug: *“the quote delete button doesn't work.”*

1. **Where:** Offerter live under **Ekonomi → Offerter**, not a top-level nav item.
2. **Go there:** `/demo` → sidebar/bottom **Ekonomi** → tab **Offerter** (`/ekonomi?flik=offerter`).
3. **States that matter:** only **Utkast** can be discarded. Sent quotes use **Inte aktuell** (→ `avbojd`), not delete.
4. **Demo fixture:** Offert **#116** `quote-bokhylla` (Eva Holmgren) is the only seeded draft.
5. **Code/data:** `DiscardDraftButton` → `discardQuoteAction` → `discardQuote()`; tables `quotes`, `quote_versions`.
6. **Verify:** see [Offerter](#offerter-quotes) → *How an agent verifies*.

## App shell & navigation

### Layout

- App chrome: `src/app/(app)/layout.tsx` — `Sidebar` + `BottomNav` (`src/components/nav.tsx`) + `main` (`lg:pl-60`, bottom padding for mobile nav).
- Root wrapper: `data-driva-demo="1"` when JSON demo **or** public demo session. Client gates read it: the shared address autocomplete (`src/components/address-input.tsx`) stays on the local Swedish example list and never calls Google when `[data-driva-demo]` is present — see [Address autocomplete](#address-autocomplete-shared).
- Back/origin: `tillbaka` + `tillbakaNamn` query params (`src/lib/nav.ts`). `AppLink` stamps origin; `SmartBack` reads it. Browser back is real history.
- Completing a send-blocker (customer email, company settings, ROT personnummer) must stamp the **document you left**, not that document's parent. Offert #6 → *Lägg till e-post* → customer Back is **Offert #6**. Helpers: `pageOrigin`, `hrefFromOrigin`. Inställningar accepts `tillbaka` even without a default back (`acceptsReturnTo`).
- Breadcrumbs = structure, never history (`structuralCrumbs`).
- Support impersonation: `SupportModeBanner` when a Driva Admin support session is active.
- Toasts (shared): `ToastProvider` wraps the whole `(app)/layout.tsx` shell; client components call `useToast().toast({ title, text?, tone?: "neutral"|"ok"|"danger", action?: { label, onClick | href }, duration?, id? })` (`src/components/toast.tsx`). Viewport `[data-toast-viewport]`, each toast `[data-toast][data-toast-tone]`, `role="status"` + `aria-live="polite"`, max 3 visible, auto-dismiss 5 s (8 s with an action, `0` = sticky), hover/focus pauses the timer, same `id` replaces instead of stacking. Sits above the mobile `BottomNav` (`--bottom-nav-h` + safe area) and centered over the content next to the desktop sidebar; `z-[100]` (above modals). Outside the provider (public pages) the hook is a silent no-op. **URL flash notices:** `FlashToast` (mounted once in the shell, inside `Suspense`) reads one-shot params via `flashFromSearch` (`src/lib/flash-notices.ts`, tests `flash-notices.test.ts`) — `?kastat=offert|faktura` (draft discarded) and `?bank=kopplad|avbrutet|fel[&meddelande=…]` (Tink callback) — shows the toast and strips the params with `router.replace`. Only catalogued keys render; free text never becomes a notice (the bank error message is the single exception and only with `bank=fel`). Users: line editor *Raden borttagen · Ångra* (`lines-editor.tsx`), `CopyLinkButton`/`ResendInvoiceButton`/`SimulatePaymentButton` in the `ActionMenu` (menu closes, toast confirms), `BankRowActions` (row leaves the list after refresh — toast stays), `PaySupplierButton`, `NewCustomerModal`. Inline feedback stays where it belongs: form errors (`role="alert"`), autosave *Sparat*, send-success cards on the document pages.
- Empty states: `EmptyState` (`src/components/ui.tsx`) always gets an `action` on list pages — filtered → *Rensa sök och filter* (`[data-clear-filters]`, resets q + status/filters + page), truly empty → the first natural step (Uppdrag: *Ny offert* + *Skapa uppdrag*; Kunder: *Ny kund*; Offerter/Fakturor: *Ny offert*/*Ny faktura*; Utgifter: *Koppla företagskontot* when no bank is connected; Inbox: *Visa allt som kommit in*; Verifikationer: *Visa alla verifikationer*; Skattekonto: *Till momsdeklarationen*). On the job page the empty *Arbete*/*Material* rows carry an inline link that opens the same sheet as the header buttons.
- Live refresh ([PR #127](https://github.com/elialm94/driva/pull/127)): `LiveRefresh` (`src/components/live-refresh.tsx`) is rendered in **both** `(app)/layout.tsx` and `(redovisning)/layout.tsx`; not on the public `/offert/*` / `/faktura/*` pages (outside the route groups). It is invisible - returns `null`, no DOM, no selector. It calls `router.refresh()` (server re-fetch; client state and scroll kept) when the tab becomes visible or the window regains focus after **≥ 1000 ms** away (`LIVE_REFRESH_MIN_AWAY_MS` - a shorter blur is focus flicker and is ignored, as is the initial focus), on `popstate` (browser Back/Forward - the App Router otherwise restores those from its client cache with zero server fetch), on bfcache `pageshow` (`persisted`) and on a `BroadcastChannel` message on `driva-live-refresh` (`LIVE_REFRESH_CHANNEL`; `{ kind: "data-changed", source: "quote-accepted" | "quote-declined", at }`). At most one refresh per **1500 ms** (`LIVE_REFRESH_MIN_INTERVAL_MS`). **Skipped** while `[data-editor-shell]` or `[data-site-editor-shell]` is in the DOM - the open form is the truth until saved. Pure, DOM-free helpers in `src/lib/live-refresh.ts` (`createLiveRefreshGate`, `announceLiveRefresh`, `isLiveRefreshMessage`; tests `src/lib/live-refresh.test.ts`). Why: `revalidatePath` in a server action only re-renders the tab that ran it, and an owner tab left open does not re-read on its own - see [Offerter](#offerter-quotes).

### Address autocomplete (shared)

One Places integration for every editable physical address — `AddressAutocomplete` (single input) + `AddressFields` (gata / postnummer / ort) in `src/components/address-input.tsx`; pure helpers in `src/lib/address-autocomplete.ts` (+ `address-autocomplete.test.ts`). **Do not fork another.**

- **Source:** Google Places API (New) when `NEXT_PUBLIC_GOOGLE_MAPS_API_KEY` is set **and** the surface is not demo. Key is read via `googleMapsApiKey()` (trimmed; empty / whitespace = not configured). `[data-driva-demo]` → local Swedish example list only, no Google HTTP. Missing key / Google failure → manual typing still works; no raw Google errors, no dead dropdown. Demo suggestions carry a **Demo** tag.
- **Behaviour:** Sweden-only (`includedRegionCodes: ["se"]`) **and** street-only results — `includedPrimaryTypes` = `premise`, `subpremise`, `street_address`, `route` (`ADDRESS_PRIMARY_TYPES`), language `sv-SE`; no map/Street View. Search from **3 meaningful characters** after trim (`"va"` does not fire), debounce 250 ms (`ADDRESS_SEARCH_DEBOUNCE_MS`). One session token per typing session; `fetchFields(["addressComponents"])` only after the user picks a suggestion. Maps loader (`referrerPolicy="origin"`) gives up after **8 s** (`ADDRESS_PLACES_LOAD_TIMEOUT_MS`); invalid key / referer block / script failure clears the searching state — **no hung spinner**, field falls back to manual typing. Opening an edit form with a saved address does **not** call Places. Picking writes street + postal + city (or one composed line); name / e-mail / phone / personnummer untouched. `composeSelected="street"` (default) vs `"line"` (`gata, postnummer ort`) for single-field forms. Live key path (real Göteborg results etc.) is **not** verified in this environment — code only.
- **Keyboard:** Arrow moves highlight; Enter picks the highlighted row when the list is open; Enter never submits the parent form while the list is **open or a search is in flight** (`searching`), so Ny kund cannot submit early; Escape closes; Tab moves on.
- **Selectors:** input `role="combobox"` `aria-expanded` `aria-autocomplete="list"`, `aria-busy` while searching; menu is portaled + viewport-flipped with `data-address-suggestions`, `z-index` 400 (`ADDRESS_MENU_Z_INDEX`, above the Ny kund modal at z=50); options `data-address-option={i}`. No `data-testid`.

| Surface | File | Mode |

| Ny kund (privat + företag) | `new-customer-modal.tsx` | `AddressFields` |
| Redigera kund | `customer-details-form.tsx` | `AddressFields` |

**Not autocomplete (do not expect it):** invoice/quote documents and public `/faktura/*` `/offert/*` (read-only); website contact/footer (company address from settings); inbox inbound e-mail address; domain registrant; fastighetsbeteckning; Land/säte fields; search boxes; supplier/kvitto extraction.

### Auth gates

Proxy (Next 16 middleware): `src/proxy.ts`. Real auth is always server-side (`ensurePageBusiness` / `withBusiness`).

**Public prefixes** (no login): `/login`, `/signup`, `/verifiera-epost`, `/glomt-losenord`, `/auth/bekrafta`, `/demo`, `/valkommen`, `/villkor`, `/integritet`, `/offert`, `/faktura`, `/sajt`, `/integritetspolicy`, `/inbjudan`, `/api/health`, `/admin/inbjudan`, `/api/auth/send-email`, `/api/inbox`, `/api/dev`. (`/api/bankid/*` is **removed** — the customer accept is a server action from `/offert/[token]`.)

`/api/kvitto/[receiptId]` is **not** public — it requires a session or demo cookie (`withBusinessRead`); without one the proxy redirects to `/login?next=/api/kvitto/…`. Same for `/api/verifikat/[id]/bilaga`, `/api/bokforing/export`, `/api/bokforing/deklaration`, `/api/inbox/bilaga/...`, `/api/betalfil/[id]` and `POST /api/grossist/prisfil` (session + same-origin check + `manage_wholesalers`).

**Read gate vs write gate** ([PR #109](https://github.com/elialm94/driva/pull/109), `src/lib/collaboration/permissions.ts`): `withBusinessRead` → `assertReadAccess` = capability `read_accounting`, which **every** role has (owner, admin, member, `accounting_consultant`, `auditor`) - so SIE export, kvitton, inbox attachments, payment files and filing downloads work from the redovisning workspace. `withBusiness` (write) → `assertWriteAccess`: with a `capability` the role matrix decides; **without** one the action is owner-surface only (*Den här åtgärden är inte tillgänglig från redovisningsytan.*). Before #109 the read path went through the write gate and denied accounting roles.

**Logged-out `/`:** rewrite to `/valkommen` (URL stays `/`). **`/valkommen`:** redirect to `/`.

**Protected + no session + no demo cookie:** redirect `/login?next=<path>`.

**Logged-in on `/login` or `/signup`:** redirect `/`. Demo sessions are **allowed** on signup (create-account from demo).

**JSON mode** (no Supabase env): proxy is passive; local `.data/db.json` is already the demo company. Production without Supabase env **hard-errors** (no silent demo).

**Page gate:** `ensurePageBusiness()` — demo loads per-session JSON; Supabase loads tenant snapshot; no memberships → `/onboarding`; accounting-only role → `/redovisning`.

## Data model overview

Postgres in `supabase/migrations/`. App aggregate `DB` in `src/lib/types.ts` (JSON mode = one snapshot). Amounts: **öre-free kronor as `bigint`**. Entity ids: **text** (uuids or seed ids like `cust-anna`).

`public.requests` existed in migration 03 and was **dropped** in `15_migrate_requests_to_jobs.sql`. Incoming website forms create **jobs**, not inbox items.

```
auth.users
  └── business_memberships (role) → businesses
        ├── business_settings (1:1; company_form ab|enskild, vat_periodicity helar|kvartal|manad, f_skatt_per_month)
        ├── business_sequences (quote / invoice / verification = serie A; verification_series JSONB = next number per serie A|M)
        ├── customers (reverse_charge_construction - företag only, DB check) → work_locations
        ├── jobs → job_work_entries (source manual|quote|ai|import|wholesaler; wholesaler_provenance JSONB)
        ├── quotes → quote_versions; signatures (1:1 = the customer's acceptance record); bankid_orders (legacy, unused by UI)
        ├── invoices (reverse_charge, frozen at issue) → invoice_line_items; invoice_issued_snapshots; payments
        ├── expenses → receipts (file: storage_path in bucket `receipts` XOR content_base64)
        ├── supplier_invoices → supplier_payments → payment_files
        ├── bank_accounts → bank_transactions; bank_connections (Tink tokens, server-only RLS)
        ├── inbox_items (attachments JSONB; file in bucket `inbox_attachments` via storage_path, or inline ≤ 1,5 MB; document_type incl. orderbekraftelse + purchase_order_id / purchase_order_confirmation_id / purchase_order_candidates)
        ├── wholesaler_connections → wholesaler_price_imports → wholesaler_products (the article catalog - outside the tenant aggregate: SQL in Supabase, file store in JSON/demo)
        ├── purchase_orders (job + connection; unique (business_id, reference); once sent: snapshot/reference/links immutable, no delete, never back to draft - trigger purchase_orders_guard) → purchase_order_lines; purchase_order_confirmations (history, no DELETE grant)
        ├── reminders; attention_states
        ├── chart_accounts (only the company's deviations from the coded BAS standard plan: custom / renamed / archived)
        ├── verifications (series A|M, transaction_date, attachment_* = underlag on the voucher) → accounting_entries
        ├── fiscal_years (label unique per business - fiscal_years_business_label_uq; start_date/end_date = calendar year by default, broken years allowed; opening_balances, opening_source, reopenings JSONB); vat_reports; assets; accruals
        ├── year_end_schedules (semesterloneskuld | kundfordringar_nedskrivning | periodiseringsfond, one per kind + year)
        ├── employees → payroll_runs (one per employee + month); employer_declarations (AGI, one per month)
        ├── annual_reports (superseded_at / superseded_reason after a reopen)
        ├── filing_submissions (moms | agi | ink2 | arsredovisning → skatteverket | bolagsverket; files = name + SHA-256 only)
        ├── websites; domains
        ├── collaboration_invitations; client_information_requests
        ├── business_onboarding (1:1 – onboarding status + Kom igång profile/task choices)
        ├── data_imports (audit of file imports, hash-unique per kind); suppliers
        └── assistant_messages; pending_actions; audit_log
```

## Demo mode

### What it is

Two layers (`src/lib/demo.ts`):

1. **`isDemoMode()`** — env: `DRIVA_DEMO=1` force on; `=0` force off; production default off; local JSON/dev default on. Gates **fake money** via `assertDemoMode` in `services/banking.ts` (**Simulera inbetalning** on a customer invoice, the simulated ROT/RUT payout, supplier **Simulera betald** without a bank); `isDemoMode() || isDemoBusiness()` also selects the legacy mock-BankID provider, the mock bank / filing providers and suppresses accept / credit notice mail. There is no “exempelkvitto” feature.
2. **`isDemoBusiness()`** — `db().meta.demo === true` from `businesses.is_demo`. Public seeded demo company in Supabase. Public `/demo` session clones also set `meta.demo = true` (`src/lib/storage/demo-session-store.ts`).

Public **Se demo** never touches tenant data (no `businesses` / `auth.users` / RLS rows). `GET /demo` (`src/app/demo/route.ts`) sets httpOnly cookie `driva_demo` (`<expiresMs>.<sessionId>`) and clones `buildSeed()` (`src/lib/seed.ts`) into the session's own store (`src/lib/storage/demo-session-store.ts`): local JSON mode → `.data/demo-sessions/<id>.json`; Supabase mode (Vercel) → one jsonb row in `public.demo_sessions` (migration 40, `state_version`-checked per-instance cache) so every serverless instance sees the same session — a file in `/tmp` was per-instance and made the Ekonomi register show stale status after a public accept ([PR #89](https://github.com/elialm94/driva/pull/89), server side); the remaining client-side staleness - an owner tab left open or restored from the App Router cache - is handled by `LiveRefresh` ([PR #127](https://github.com/elialm94/driva/pull/127), see [Layout](#layout)). Incognito = new clone.

Logged-in real user hitting `/demo` → `/`. Prefetch → 204. Rate limit fail → `/login?demo=upptagen`. Cookie TTL default 24h (1–72). Expired cookie → landing.

- **Purpose:** Persistent, resumable list of what remains — derived from real data, never a blocking wizard.
- **Routes:** Hem card `src/components/setup/setup-home-card.tsx` (`data-setup-home-card`, max 3 open tasks, link *Alla steg*); `/installningar?flik=kom-igang` → `setup-center.tsx` (`data-setup-center`): profile (`setup-profile-form.tsx`, `data-setup-profile-edit|save`), *Att göra*, *Fler saker du kan göra*, *Gör senare*, *Behövs inte*, *Klart*, *Genomförda importer* (`data-setup-imports`), button **Ladda upp filer** → `/kom-igang/importera`.
- **Tasks (`src/lib/setup/tasks.ts`):** `move_bookkeeping` (done when a `bokforing` import is imported; hidden for *nystartat*), `invite_consultant` (done via `hasCollaborationUsage`), `first_customer`, `first_job`, `payment_details` (done when readiness has no payment blocker), `connect_bank` (done when `bankConnectionView().status === "connected"`), `articles_prices` (done when an active wholesaler price import exists; recommended for El/VVS; when the feature is off the CTA activates it via `activateOptionalFeatureAction` and lands on Grossister). `payroll` is **hidden** (`relevance: "hidden"`, *Lön finns inte i Ferva ännu*) and the profile answers *Ja, till mig som ägare* / *Ja, till anställda* with *Lönehantering finns inte i Ferva ännu – vi hör av oss när det finns.* — this text predates [PR #109](https://github.com/elialm94/driva/pull/109) and contradicts the owner **Lön** tab (`/bokforing/lon`, one employee). Known copy gap; do not treat Kom igång as the way to reach Lön.
- **Status:** todo | in_progress | done | later | not_needed. Only `later` / `not_needed` are stored (`taskOverrides`); `done` always wins. Row selectors: `[data-setup-task=<id>][data-setup-status=…]`, actions *Senare*, *Behövs inte* (not for bank/payment/customer), *Ta upp igen* (`data-setup-reactivate`), *Visa*.
- **Priority:** bookkeeping=existing → *Flytta in bokföringen* first; consultant → *Bjud in din redovisningskonsult* first; new → customer/job; payment details jump first once quotes/invoices exist. Optional (non-recommended) tasks never show on Hem. Card disappears when no recommended task is open, and is never shown to backfilled existing companies without a profile that already have customers/jobs; center stays reachable.
- **Actions:** `setSetupTaskAction`, `updateSetupProfileAction` (`src/app/onboarding-actions.ts`).
- **Verify:** `scripts/verify-onboarding-browser.ts` (profile save, Senare/Ta upp igen, Hem card order). Tests: `src/lib/setup/setup.test.ts`.

## Flytta dina uppgifter till Ferva (import)

- **User-facing name:** Flytta dina uppgifter till Ferva
- **Purpose:** Upload what you have (SIE bookkeeping, customer/supplier registers, wholesaler price lists); Ferva identifies each file, previews exactly what will be created/omitted and imports only after an explicit confirmation.
- **Route:** `/kom-igang/importera` — `src/app/(app)/kom-igang/importera/page.tsx` + `src/components/imports/import-center.tsx`. API: `POST /api/kom-igang/import` (multipart, `mode=analyze|import`, `options` JSON; capability `import_data` = owner/admin; Origin check; max 25 MB; file never stored).
- **Flow:** dropzone (since [PR #125](https://github.com/elialm94/driva/pull/125) the shared `FileDropzone` landing variant with `multiple`, title *Dra filer hit eller välj från enheten*; still `data-import-dropzone` on the zone and `data-import-file-input` on the hidden `input[type=file]`, *Vilka filer fungerar?* toggle inside the zone; the zone has no `role="button"` here because it carries children) → per-file card (`data-import-card[data-import-state=reading|checking|ready|importing|done|failed]`, `data-import-kind`) with real progress *Läser filen → Kontrollerar innehållet → Redo att granskas* → choices (SIE years `data-import-year`, register mapping “Vi tror att dessa kolumner hör ihop” `data-import-field=<field>`, article connection `data-import-connection`, unknown → `data-import-kind-select`) → **Importera** (`data-import-confirm-open`) → confirmation box (`data-import-confirm`, `data-import-run`) → done card (`data-import-state=done`, `data-import-summary`, link to next view). *Kontrollera detaljer* (`data-import-details`) lists unbalanced verifications, duplicates, review rows, unused columns.
- **Detection (`src/lib/services/data-imports.ts`):** SIE by content (`looksLikeSieBytes`/`parseSie`); PDF → unsupported (points to Inbox); tables via the wholesaler readers (`parsePriceFile`: CSV/TXT/XLSX/XML/ZIP) then `classifyRegisterTable` (kunder / leverantorer / artiklar / unknown). AI (`src/lib/imports/classify-ai.ts`) only **suggests** kind + mapping when deterministic detection fails and a key exists; result is badged *AI-förslag* and confirmed by the user. Without AI everything works manually.
- **Imports:** bokföring → `applySieImport` (see docs/onboarding-import.md); kunder → `Customer` rows (+ work locations for fastighetsbeteckning), suppliers → `suppliers` table (listed under Ekonomi → Utgifter, `data-supplier-register`); artiklar → **existing** `importPriceFile` of Grossistbeställningar (needs active feature + connection; no second catalog). Audit row `data_imports` per import (user, hash, counts, warnings, choices, summary); unique `(business, kind, hash)` for imported files → *redan inflyttad*.
- **Invariants:** nothing is written before confirmation; the confirmation upload must hash-match the analysis; one import per file+kind; SIE never imports an unbalanced verification; year conflicts default to skip; no file content is logged or stored.
- **Series counters after a SIE import** ([PR #119](https://github.com/elialm94/driva/pull/119), migration `41_sie_import_series_counter`): imported verifications keep the file's serie + number (unnumbered ones and balances-only years get serie `SIE`, `source.type = "sie_import"`). Afterwards **both** the legacy `sequences.verification` column **and** `sequences.verificationSeries.A` must be ≥ max(imported A) + 1: domain `applySieImport` sets both; on Supabase the commit sends `sie_import` verifications through SQL `app.import_verification` (no CAS, runs **before** the app's own `app.post_verification` calls) which updates the column and the `verification_series` jsonb (serie A in both, other series in jsonb only); `loadTenantState` reads A as `Math.max(column, jsonb)` so a jsonb left behind by an older import can never pull A below the column. Why it matters: `postVerification` (`allocateNumberInSeries` in `accounting/series.ts`) and `app.post_verification` read the jsonb series **first**, so a stale jsonb A after an import handed the next own verification an already-used number (or `sequence_conflict` in the CAS). Not to be confused with the `/bokforing/ingaende-balans` SIE panel, which imports opening balances only and never touches the counters.
- **Verify:** `scripts/verify-onboarding-browser.ts` (CSV upload → mapping → import → done → duplicate refused → Kunder list → Genomförda importer). Tests: `src/lib/imports/sie.test.ts` (incl. `sequences.verification` and `verificationSeries.A` after import, next own verification does not collide), `src/lib/imports/registers.test.ts`, `scripts/db-validate.ts` (import_verification advances `verification` **and** `verification_series ->> 'A'`, data_imports index, RLS), `scripts/adapter-validate.ts` (SIE through commit).

### Kvittotolkning (AI vision)

- **Hook:** `extractReceipt` in `src/lib/ai/extract-document.ts`. Returns an `InboundParsedHint` with per-field confidence. Usage is logged to `assistantAudit` as `llm_document_extract`.
- **The model never gets the last word.** Its self-reported confidence is capped at `MODEL_CONFIDENCE_CEILING = 0.9`, below `CONFIDENCE_THRESHOLDS.AUTO` (0.98). A reading only crosses the auto-booking threshold on evidence outside the model (`src/lib/inbox/corroborate.ts`): VAT arithmetic that resolves to a legal Swedish rate (25/12/6 %, ±1 kr) raises it to 0.95 (a strong suggestion), and an exact amount match against an unbooked outgoing bank transaction raises it to 0.99 (auto). Document confidence is the *weakest* of supplier/amount/VAT, never an average.
- **Where it runs:** before ingest, inside the tenant context — `interpretInboundPayload` for inbound mail (both `/api/inbox/inbound` and `/api/inbox/inbound/resend`) and `interpretDocumentFile` for uploads. A sender-supplied `parsed` always wins, so nothing is re-interpreted. A failed or absent interpretation leaves the payload untouched and the document goes to `/inbox/[id]/kontrollera` — the same path as before AI.
- **Not configured:** without `OPENROUTER_API_KEY` the interpretation is skipped entirely and every document lands in the Inbox for review. Nothing is fabricated.
- **Tests:** `src/lib/receipt-extraction.test.ts` (parsing, ceiling, evidence rules, ingest wiring).
- **DB:** `expenses`, `receipts` (`storage_path`, `content_type`, `size_bytes`, `content_base64` — migration `26_receipt_content`; check `receipts_one_storage_chk`: never both `storage_path` and `content_base64`), `supplier_invoices`, `supplier_payments`. Bucket `receipts`.
- **Verify:** `/demo` → `/bokforing` (*Behöver lösas*; on Hem it may sit inside the grouped *N bokföringsfrågor* item) → *Kvitto saknas – Clas Ohlson, 349 kr* (`exp-clas`) → the compact **Lägg till kvitto** zone (`[role="button"][aria-label="Lägg till kvitto"]`; drop a file on it or set the hidden `input[type=file]` next to it) → a PNG/PDF ≤ 1,5 MB (a 1,2 MB file must work) → row resolves with *Kvitto sparat och matchat* → Ekonomi → Utgifter → Clas Ohlson row shows *Kvitto · Bokfört* + **Visa kvitto** → link opens `/api/kvitto/<id>` with the file. ## Grossistbeställningar (wholesale orders)

- **User-facing name:** Grossistbeställningar (feature) · Grossister (settings tab) · Materialbeställningar (job section).
- **Purpose:** Electricians/plumbers connect their wholesalers (`WHOLESALER_KEYS`: Ahlsell, Dahl, Sonepar, Solar, Lundagrossisten, Rexel, *Annan grossist*), upload price lists / discount letters, search articles with **their own purchase prices**, build a cart per job, e-mail the order to the wholesaler and get the order confirmation matched back in the Ferva inbox. Optional feature — **invisible when off**: no nav item, the job material UI is unchanged.
- **Feature flag:** `wholesalers` in `src/lib/optional-features.ts` / `features.ts` (`wholesalersEnabled(db)`, `hasWholesalerUsage` backfills for existing data). Copy: *Sök material med dina priser och skicka beställningar till grossisten.* Deactivation never deletes connections, price files, articles or order history.
- **Routes:** settings `/installningar?flik=grossister` (redirects to `?flik=funktioner` while the feature is off); order detail `/uppdrag/[id]/bestallning/[orderId]` (crumbs *Uppdrag / {job} / Beställning FV-{n}*, nav label *Materialbeställning*, back **Uppdraget**; 404 unless the order belongs to that job); price-file upload `POST /api/grossist/prisfil` (multipart, max 8 MB, same-origin check, `manage_wholesalers`, `mode=preview|import`, CSV/TXT/XLSX/XML/ZIP only; a route handler because the files exceed what a server action body takes as base64; **not** a public prefix). Inbox items of type `orderbekraftelse` render `inbox-order-confirmation.tsx` (no invoice fields). No page of its own and no nav item.
- **Settings (Grossister):** `wholesaler-settings.tsx`. **Lägg till grossist** → modal (**Spara grossist**; field ids end in `-grossist`, `-kundnummer`, `-ordermejl`). Per connection: wholesaler, display name, customer number, order e-mail (user-entered — Ferva never guesses), CC self, default pickup/delivery + store/address, contact, phone, customer price rule (*Ange kundpris senare* | *Beräkna med påslag på inköpspriset* | *Använd utpris från prisfilen*), **Ändra**, **Aktivera** / **Inaktivera** (inactive connections drop out of the job search but keep their data). Den nuvarande prislistan påverkas inte förrän du bekräftar.*, formats *CSV, TXT, Excel, XML eller ZIP · max 8 MB*; `[data-price-file-input]` stays on its hidden input, the old *Välj prisfil* label is gone).
- **Import engine (`src/lib/wholesalers/`):** `file-detect.ts` (CSV/TXT/TSV/XLSX/XML/ZIP, BOM/UTF-8/Windows-1252), `csv.ts` (delimiter sniffing, Swedish decimals), `xlsx.ts` + `zip.ts` (own minimal readers; zip-bomb/ratio/entry limits, no nested archives, path traversal rejected), `xml.ts`/`xml-table.ts` (no DTD/entities), `table.ts` (formula-injection neutralised, row/column limits), `column-mapping.ts` (Swedish/English header synonyms + content heuristics; mapping remembered per connection), `import-engine.ts` (preview → validate → build). **Price rules:** explicit net price wins; otherwise list price × (1 − discount group %) from a discount letter stored on the connection; sales price from file only if that rule is chosen; else markup; never invents a price. Money = integer öre (`money.ts`); customer prices are whole kronor. **Atomic:** import row `processing` → products written under new `import_id` → activate + supersede old in a separate commit; failure leaves the previous list active (`status=failed`, `failed_reason`, row-level `errors[]` with line numbers).
- **Catalog storage:** `wholesaler_products` live **outside** the tenant aggregate: Supabase → SQL (`catalog-store-sql.ts`, indexes on article/E/RSK/GTIN keys + trigram on `search_text`); JSON/demo sessions → file/memory store (`catalog-store.ts`, `.data/wholesaler-catalog/`). **Always start from a clean demo:** `/demo` or Återställ demo. Seed ids above are valid after reset.

| Task | Steps |
|------|-------|
| Open Offerter | `/demo` → **Ekonomi** → tab Offerter (default) |
| Delete a quote | Only #116 → *Kasta utkast* → confirm. Sent quotes: Hem *Inte aktuell* or public *Avböj*. |
| Accept a quote | `/offert/demo-bertil-fasad` → accept chrome **below** the document → name → Godkänn offert. An owner tab left on Ekonomi → Offerter in the same browser flips #115 to **Godkänd** by itself; Back/Forward or refocus after ≥ 1 s re-fetches too ([PR #127](https://github.com/elialm94/driva/pull/127)) |
| Overdue invoice | `/ekonomi/fakturor/inv-1042` |
| Inbox badge item | `/inbox/inbox-mail-byggmax` |
| Upload a receipt file | `/bokforing` → *Kvitto saknas – Clas Ohlson, 349 kr* → compact zone `[role="button"][aria-label="Lägg till kvitto"]` (drop a file, or set the `sr-only` `input[type=file]` next to it; file < 1,5 MB) → *Kvitto sparat och matchat* → Ekonomi → Utgifter → **Visa kvitto** |
| Upload to the Inbox (no purchase) | Ekonomi → Utgifter → zone **Släpp kvitton här**, or `/inbox` → zone **Släpp kvitton och fakturor här** (`[data-receipt-upload]`; drop, click, or Ctrl/Cmd+V anywhere on the page) → a ~1,2 MB PNG/PDF works (old data-URL cap was ~730 KB) → `[data-receipt-upload-row][data-status="klar"]` with *Bokfört* / *I inboxen – kontrollera uppgifterna*; > 5 MB → `data-status="fel"` *För stor ({size}) – max 5 MB.* with zero requests; several files queue and upload one at a time. Verifikat underlag: `/bokforing/verifikationer/nytt` → zone **Släpp underlaget här** > 10 MB → *Underlaget är för stort (max 10 MB).* at selection |
| Address autocomplete (demo) | `/demo` → Kunder → **Ny kund** → type `Väd` in **Adress** → `[data-address-suggestions]` with **Demo** tag → pick → adress + postnummer + ort filled |
| Manuellt verifikat | `/bokforing/verifikationer` → **Nytt verifikat** → *Vad har hänt?* + two rows (e.g. 6991 debet 100 / 1930 kredit 100) → **Bokför verifikatet** → *M1 är bokförd på 100 kr* → **Öppna M1** |
| Skattekonto F-skatt | `/bokforing/skattekonto` → **Bokför F-skatt 2026-01** → row in *Rörelser på kontot*, saldo −12 400 kr **Skuld**; the *Skattekontot är inte à jour* attention row drops one month |
| Lön (owner) | `/bokforing/lon` → **Lägg upp lönen** (`#lon-namn`, `#lon-pnr` valid 12-digit pnr, `#lon-belopp`) → **Bokför lön {månad}** → row in *Lönekörningar* → open month → lönespecifikation → **Hämta deklarationsfil (XML)** on the AGI card |
| Stäng en månad | `/bokforing/periodstangning` → *Nästa period att stänga* → **Stäng januari 2026** → **Ja, stäng perioden** → badge *Till och med 2026-01-31*; `/bokforing/verifikationer/nytt` now has `min` = 2026-02-01 |
| Omvänd byggmoms | `/kunder/cust-nord` → tick **Omvänd byggmoms** → Ekonomi → **Ny faktura** for Nord Studio AB → lines forced to 0 %, note *Omvänd byggmoms.* → document totals read *Moms – omvänd byggmoms* + section **Omvänd byggmoms** |
| Deklarationsfil / arkiv | `/bokforing/moms` → open *Visa underlag per deklarationsruta* on a non-ongoing period → **Hämta deklarationsfil (eSKD)** (`momsdeklaration-2026-K2.xml`); `/api/bokforing/export?typ=arkiv&ar=2026` → zip with `LÄSMIG.txt` + `underlag/register.csv` |
| Räkenskapsår (set / view) | `/installningar?flik=foretag` → **Räkenskapsår** card → click `#installningar-rakenskapsar-slut` → *Nästa månad* ×6 → **30** (2027-06-30; keeps the seed's 2026 verifications inside the year) → **Spara räkenskapsår** → *Sparat*, line *2026/2027: 1 januari 2026–30 juni 2027* → `/bokforing/huvudbok` subtitle *… 2026-01-01 till 2027-06-30 …*, **Exportera CSV** `ar=2026%2F2027`, still no chips → back on the card **Skapa nästa år** → list *2026/2027* + *2027/2028 · 1 juli 2027–30 juni 2028*, button gone → Huvudbok / Resultat / Saldobalans / Balans / Moms / Bokslut show the two chips (`?ar=2026%2F2027`, `?ar=2027%2F2028`); `/bokforing/bokslut?ar=2027%2F2028` → *Bokslut 2027/2028*; `?ar=1999` falls back to the current year. Clicked through on JSON dev 2026-09-08; Återställ demo undoes it |
| Enable Samarbeta | `/installningar?flik=funktioner` → Aktivera Samarbeta |
| Grossistbeställning (`/demo` on driva-alpha or JSON dev) | `/installningar?flik=funktioner` → **Aktivera** Grossistbeställningar → lands on **Grossister** with *Demo-grossisten* (*Dina priser uppdaterades …*) → `/uppdrag/job-kok` → **Lägg till material** → type `kabel` in `[data-wholesaler-search]` → **Lägg i varukorg** → **Visa varukorg (1)** → **Granska beställning** (`[data-wholesaler-mail-preview]` shows `order@demo-grossisten.example`, `DEMO-4711`, `bestallning-FV-1001.pdf`) → **Skicka beställning** → *Inget mejl lämnade Ferva* → **Klar** → job section *Materialbeställningar* lists `FV-1001 · Demo-grossisten` → `/inbox?visning=alla` has *Orderbekräftelse Demo-grossisten · FV-1001* linked to the order (`[data-inbox-linked-order]`). **Stäng av** afterwards: the section stays, the search is gone |
| Accountant UI | Company row → Visa redovisningsvyn |
| Auth wall | Incognito `/kunder` → login with `next=/kunder` |

Local: `npm run dev` → http://localhost:3123 (JSON demo, no `/demo` needed). Do not kill a healthy process on 3123.
